# 待办提醒系统性能优化

> 日期：2026-03-25  
> 涉及文件：`src/app.py`、`src/skills/todo_manage.py`

## 背景

TextAgent 的待办提醒采用 **1 分钟心跳**（`todo_remind_tick`）机制，每分钟遍历所有活跃用户、读取 state 文件和 Todo.md，调用 `check_todos()` 判断是否有到期待办需要推送。

随着用户数增长，每分钟的 IO 开销线性增加。但实际上，绝大多数心跳轮次中，用户的待办都还没到触发时间，全量检查是不必要的。

### 核心矛盾

- **不能降低心跳频率**：一次性提醒的容差窗口很窄（原先仅 1 分钟），降频会导致错过提醒
- **不能延迟发现新待办**：用户可能随时添加新待办，`todo_remind_tick` 每次绕过缓存直接读 state 文件来保证发现及时性
- **需要降低每次心跳的开销**：让"无事可做"的心跳尽快返回

## 优化方案

### 1. 智能预检机制（核心优化）

**文件**：`src/app.py` — `todo_remind_tick` 逻辑

在调用 `check_todos()`（涉及 Todo.md 文件读写、交叉验证等重操作）之前，增加一轮**纯内存预检**：

```
state 文件读取（不变，保证新待办被发现）
    ↓
遍历 state["todos"]，纯内存判断：
    ├─ 循环待办：今天已推过？→ 跳过
    ├─ 循环待办：有 remind_at 且当前时间未到？→ 跳过
    ├─ 一次性提醒：不是今天的？→ 跳过
    ├─ 截止日期：不是今天且未过期？→ 跳过
    └─ 有任何一条命中 → has_potential = True
    ↓
has_potential = False → 直接 continue，不调 check_todos()
has_potential = True  → 正常进入 check_todos() 详检
```

**效果**：心跳频率不变（1 分钟），但大多数心跳在微秒级完成预检后直接跳过，只有真正有到期待办的用户才会触发完整检查。

### 2. 扩大一次性提醒容差窗口

**文件**：`src/skills/todo_manage.py` — `check_todos()` 函数

| 项目 | 优化前 | 优化后 |
|------|--------|--------|
| 触发条件 | `diff_minutes <= 1` | `diff_minutes <= 2` |
| 含义 | 到期前 1 分钟内才触发 | 到期前 2 分钟内触发 |

**原因**：容差窗口从 1 分钟扩大到 2 分钟，为心跳偶发延迟留出余量。配合 `last_notified` 防重复机制，保证不会重复推送。

### 3. 清理意图队列中的残留代码

**文件**：`src/app.py`

`todo_remind` 已经从意图队列模式独立为心跳驱动模式，但以下两处仍保留着废弃引用：

- `_MERGEABLE` 集合中的 `("morning_report", "todo_remind")` → **已移除**
- `action_map` 字典中的 `"todo_remind": "todo_remind"` → **已移除**

清理死代码，减少维护混乱。

## IO 开销对比

假设 10 个活跃用户，每人平均 5 个待办，其中 2 个当天需要触发：

| 指标 | 优化前（每分钟） | 优化后（每分钟） |
|------|------------------|------------------|
| `state_file` 读取 | 10 次 | 10 次（不变） |
| `check_todos()` 调用 | 10 次 | **~2 次** |
| `Todo.md` 读取 | 10 次 | **~2 次** |
| `Todo.md` 写入 | ~1 次 | ~1 次（不变） |
| **总 IO 次数** | **~31 次/分钟** | **~14 次/分钟** |

## 可靠性验证

| 场景 | 是否受影响 | 说明 |
|------|-----------|------|
| 新添加的待办能否被及时发现 | ✅ 不受影响 | 仍然每分钟绕过缓存读 state 文件 |
| 一次性提醒能否按时触发 | ✅ 更可靠 | 容差从 1→2 分钟，预检不阻断 |
| 循环待办能否每天推送 | ✅ 不受影响 | 预检会正确识别"今天未推"的循环待办 |
| 截止日期提醒 | ✅ 不受影响 | 预检会正确识别当天/过期待办 |

## 设计原则

1. **心跳频率不降**：保证提醒的及时性和新待办的发现速度
2. **预检纯内存**：不引入额外 IO，只利用已读取的 state 数据
3. **向后兼容**：不改变 `check_todos()` 的行为，只在外层减少调用次数
4. **防重复不变**：`last_notified` / `pre_notified` / `overdue_notified` 机制完整保留
