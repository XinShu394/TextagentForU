# 2026-03-26 多用户扩展：SQLite 存储层 & 生产级基础设施

> 目标：将 TextAgent 从 2 人规模扩展到 20–100 人，消除文件 I/O 瓶颈，引入生产级服务器。

---

## 一、背景与动机

TextAgent 原始架构使用 JSON 文件存储用户、Token、邀请码、公告等系统数据。当用户量从 2 人增长到 20+ 人时，面临以下问题：

| 问题 | 影响 |
|---|---|
| 文件读写无锁 | 并发请求导致数据竞争、文件损坏 |
| 每次操作全量读写 | 用户增多后 I/O 时间线性增长 |
| Flask dev server | 单线程阻塞，不支持优雅重启 |
| 无结构化查询 | 统计、聚合只能全量加载后内存计算 |

## 三、Phase 0：生产级基础设施

### 3.1 gunicorn 替代 Flask dev server

**变更文件：** `deploy/crontab/entrypoint.sh`

- 使用 `gunicorn` 作为 WSGI 服务器（替代 `python app.py`）
- 支持环境变量配置：`GUNICORN_WORKERS`、`GUNICORN_THREADS`、`SERVER_PORT`
- 默认 1 worker / 4 threads（SQLite 单写安全）
- 启动命令：`exec gunicorn "app:create_app()"`

### 3.2 应用工厂模式

**变更文件：** `src/app.py`（新增 `create_app()` 和 `_do_init()`）

```python
def create_app():
    """Flask 应用工厂 — 供 gunicorn 调用"""
    _do_init()
    return app

def _do_init():
    """一次性初始化（带去重守卫）"""
    global _app_initialized
    if _app_initialized:
        return
    _app_initialized = True
    # ... 初始化逻辑
```

- `_do_init()` 使用 `_app_initialized` 守卫，确保多 worker 下只初始化一次
- `if __name__ == '__main__'` 保留直接运行能力

### 3.3 依赖版本锁定

所有依赖固定到精确版本，新增：

## 四、Phase 1a：SQLite 存储层

### 4.1 新增文件：`src/db.py`（875 行）

这是整个存储层的核心，提供 SQLite WAL 模式的结构化存储。

#### 数据库配置

| 配置项 | 值 | 说明 |
|---|---|---|
| 存储路径 | `data/_textagent_system/textagent.db` | 与现有系统目录共存 |
| WAL 模式 | `PRAGMA journal_mode=WAL` | 读写并发，不锁全库 |
| busy_timeout | 10000ms | 写冲突时最多等 10 秒 |
| synchronous | NORMAL | 平衡性能与安全 |
| 线程安全 | `threading.local()` | 每线程独立连接 |

#### 数据库表结构（8 张表 + schema_version）

```
┌──────────────────┬──────────────────────────────────────┐
│      表名         │              用途                     │
├──────────────────┼──────────────────────────────────────┤
│ schema_version   │ 数据库版本管理（未来 ALTER TABLE）     │
│ users            │ 用户信息（状态、昵称、消息统计等）      │
│ tokens           │ Web 访问令牌（自动过期）               │
│ invite_codes     │ 邀请码（使用次数/上限/过期）           │
│ announcements    │ 系统公告                              │
│ feedbacks        │ 用户反馈 + 管理员回复                  │
│ decision_logs    │ AI 决策日志（Skill/模型/耗时）         │
│ usage_logs       │ LLM Token 用量（按次记录）             │
│ audit_logs       │ 操作审计日志                          │
└──────────────────┴──────────────────────────────────────┘
```

#### Manager 类

每张表对应一个 Manager 类，提供类型安全的 CRUD 方法：

| Manager | 核心方法 |
|---|---|
| `UserManager` | `get_or_create_user()`, `increment_message_count()`, `get_all_active_users()`, `update_status()`, `delete_user()` |
| `TokenManager` | `generate_token()`, `verify_token()`, `cleanup_expired()` |
| `InviteCodeManager` | `create_code()`, `use_code()`, `get_all()`, `delete_code()` |
| `AnnouncementManager` | `create()`, `get_all()`, `delete()` |
| `FeedbackManager` | `create()`, `get_all()`, `reply()` |
| `DecisionLogManager` | `write_decision_log()`, `get_recent()` |
| `UsageLogManager` | `log_usage()`, `get_monthly_cost()`, `get_daily_stats()`, `get_model_stats()` |
| `AuditLogManager` | `log()` |

#### DataMigrator — 一次性迁移

`DataMigrator.migrate_all()` 在首次启动时自动执行，将 JSON 文件数据迁移到 SQLite：

- `users.json` → `users` 表
- `tokens.json` → `tokens` 表
- `invite_codes.json` → `invite_codes` 表
- `announcements.json` → `announcements` 表
- `feedbacks.json` → `feedbacks` 表
- `usage_log.jsonl` → `usage_logs` 表

迁移是 **幂等** 的（通过 UNIQUE 约束 + INSERT OR IGNORE）。

#### 降级开关

```bash
# 设置环境变量可完全回退到文件存储
export TEXTAGENT_DB_DISABLE=1
```

设置后所有 db 单例置为 `None`，下游代码自动走 JSON fallback 路径。

## 五、Phase 1b：双路由迁移

### 5.1 设计原则

所有公共函数采用 **SQLite-first, JSON-fallback** 的双路由模式：

```python
def some_function(user_id, ...):
    # SQLite 路径
    if _db_xxx is not None:
        return _db_xxx.some_method(user_id, ...)
    # JSON fallback（原有逻辑，一行不改）
    ...原有代码...
```

这保证了：
- **零停机迁移**：SQLite 可用时自动使用，不可用时无缝回退
- **原有逻辑零修改**：fallback 路径保持原样
- **渐进式上线**：通过环境变量随时切换

## 七、架构变化示意

### Before（文件存储）
```
请求 → Flask dev server（单线程）
        ↓
    读 users.json（全量加载）
    写 users.json（全量回写）
    读 tokens.json ...
    写 usage_log.jsonl ...
```

### After（SQLite + gunicorn）
```
请求 → gunicorn（多线程/多进程）
        ↓
    SQLite WAL（行级读写，无全量加载）
    ↓
    如 SQLite 不可用 → 自动 fallback 到 JSON
```

## 八、数据迁移说明

### 自动迁移

首次启动时 `DataMigrator.migrate_all()` 自动执行，将现有 JSON 数据导入 SQLite。

### 手动验证

```bash
# 进入 SQLite 查看数据
sqlite3 data/_textagent_system/textagent.db

# 查看用户数
SELECT COUNT(*) FROM users;

# 查看月度用量
SELECT user_id, SUM(total_tokens) FROM usage_logs
WHERE ts >= date('now', 'start of month')
GROUP BY user_id;
```

### 回退方案

```bash
# 1. 停止服务
# 2. 设置环境变量
export TEXTAGENT_DB_DISABLE=1
# 3. 重启服务（自动回退到 JSON 文件）
```
