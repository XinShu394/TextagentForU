# 2026-03-30 安全加固与稳定性修复

## 概述

本次对 TextAgent 核心代码进行了系统性的安全审计与修复，涵盖**崩溃级 Bug 修复**、**安全漏洞修补**、**线程安全加固**、**数据完整性保护**和 **Token 优化**五个维度，共计 **15 项修复**。

---

## P0 — 崩溃级 Bug 修复

### 1. `memory.py` — `create_storage()` 缺少必需参数

- **文件**: `src/memory.py` (第 59 行)
- **问题**: `PromptCache.get()` 回源时调用 `create_storage()`，但该函数需要 `storage_mode` 参数，导致 `TypeError` 崩溃
- **修复**: 传入 `"local"` 作为默认 storage_mode

### 2. `brain.py` — `t_llm` 变量未初始化

- **文件**: `src/brain.py` (第 798 行)
- **问题**: Flash 路径中 `call_llm` 失败时，`t_llm` 未被赋值，后续 `_log` 引用时触发 `NameError`
- **修复**: 在 Flash 路径入口处初始化 `t_llm = t_state` 作为兜底值

---

## P0 — 安全漏洞修复

### 3. `user_context.py` — 路径遍历（Path Traversal）防护

- **文件**: `src/user_context.py` (第 67 行)
- **问题**: `user_id` 直接拼接文件路径，攻击者传入 `../../etc` 可穿越目录读取敏感文件
- **修复**: 在 `UserContext.__init__` 中校验 user_id，拒绝含 `..`、`/`、`\` 的输入

### 4. `app.py` — XXE（XML 外部实体注入）防护

- **文件**: `src/app.py` (第 313 行)
- **问题**: `ET.fromstring(xml_data)` 直接解析未经检查的 XML，可能遭受 XXE 攻击
- **修复**: 新增 `_safe_parse_xml()` 函数，拒绝包含 `<!DOCTYPE>` / `<!ENTITY>` 声明的 XML 输入；替换所有 `ET.fromstring()` 调用

### 5. `app.py` — 内部端点鉴权

- **文件**: `src/app.py`
- **问题**: `/process`、`/system`、`/admin/menu` 三个内部端点无任何鉴权，任何人可直接调用
- **修复**: 新增 `_is_internal_request()` 校验函数，仅允许本机回环 IP、Docker 网桥 IP 或携带正确 `X-Internal-Secret` Header 的请求通过

### 6. `app.py` — SSRF（服务端请求伪造）防护

- **文件**: `src/app.py` (第 383 行 `_fetch_link_content`)
- **问题**: 用户发送 `http://169.254.169.254/latest/meta-data/` 等链接可触发 SSRF，读取云服务器元数据
- **修复**: 在链接抓取前校验目标 hostname，拦截内网 IP 段（10.x、172.16-31.x、192.168.x、127.x）和云元数据地址

## P1 — 线程安全加固

### 7. `app.py` — 消息去重缓存加锁

- **文件**: `src/app.py`
- **问题**: `_processed_msg_cache` 全局字典在多线程并发写入时可能导致数据损坏
- **修复**: 添加 `_msg_cache_lock = threading.Lock()`，所有读写操作在锁内完成

### 8. `app.py` — 企微 Token 缓存加锁

- **文件**: `src/app.py`
- **问题**: `_wework_token_cache` 全局字典在并发刷新 Token 时可能发生竞态
- **修复**: 添加 `_wework_token_lock = threading.Lock()`，Token 读取和更新在锁内完成

### 9. `brain.py` — 告警状态加锁

- **文件**: `src/brain.py`
- **问题**: `_alert_state` 全局字典（slow_count、last_alert_time、_call_count）在多线程并发更新时计数不准
- **修复**: 添加 `_alert_lock = threading.Lock()`，所有 `_alert_state` 的读写在锁内完成；冷却时间在锁内预先占位防止重复告警

## P1 — 数据完整性保护

### 10. `user_context.py` — JSON 文件原子写入

- **文件**: `src/user_context.py`
- **问题**: `_write_registry()`、`_write_tokens()`、`save_user_config()` 直接 `open → write`，中途崩溃（断电、OOM kill）会导致 JSON 文件损坏
- **修复**: 全部改为 **write → fsync → os.replace** 原子写入模式：先写临时文件，刷盘后重命名覆盖原文件

### 11. `brain.py` — 多步 steps 中 `note.save` 数据丢失

- **文件**: `src/brain.py` (第 1244 行 `_execute_steps`)
- **问题**: 当 LLM 返回多步 steps（如 `[chat, note.save]`）时，`note.save` 被注释"已由统一写入处理"而跳过执行。但 `_get_primary_skill()` 只取 `steps[0]`，导致 `note.save` 既不在 steps 中执行也不被顶层 `_save_to_quick_notes` 调用 —— **用户笔记数据丢失**
- **修复**: 在 `_execute_steps` 中不再跳过 `note.save`，改为直接通过 handler 执行

## P2 — 稳定性改进

### 12. `brain.py` — 告警参数校验

- **文件**: `src/brain.py` (`_check_and_alert`)
- **问题**: `elapsed` 参数可能为 None 或非数字类型，导致后续比较崩溃
- **修复**: 添加 `float()` 转换兜底，异常时默认为 0

---

## P3 — Token 优化

### 13. `brain.py` — `page_content` 截断

- **文件**: `src/brain.py` (`_build_user_message`)
- **问题**: 网页抓取内容 `page_content` 直接透传给 LLM，无长度限制，可能灌入数万 token
- **修复**: text 类型和 link 类型的 `page_content` 均截断到 **1500 字符**

### 14. `brain.py` — `memory.md` 截断

- **文件**: `src/brain.py` (`build_system_prompt`)
- **问题**: 长期用户的 `memory.md` 持续增长，导致 system prompt 过长、token 消耗飙升
- **修复**: `memory` 内容超过 **3000 字符** 时截断并标注 `...(记忆已截断)`
