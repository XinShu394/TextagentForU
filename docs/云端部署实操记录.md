## 三、常用操作命令

### 3.1 更新代码并重启（推荐使用 systemctl）

```bash
cd /opt/karvis && git pull origin main && sudo systemctl restart karvis
```

### 3.2 查看运行状态

```bash
sudo systemctl status karvis
```

或者：

```bash
ps aux | grep app.py
```

### 3.3 查看实时日志

```bash
journalctl -u karvis -f
```

或者：

```bash
tail -f /opt/karvis/karvis.log
```

### 3.4 查看最近日志（最后100行）

```bash
journalctl -u karvis --no-pager | tail -100
```

### 3.5 仅重启（不更新代码）

```bash
sudo systemctl restart karvis
```

### 3.6 查找项目位置（如果忘记了）

```bash
find / -name "app.py" -path "*/karvis/*" 2>/dev/null
```

## 四、Systemd 服务配置

服务配置文件位置：`/etc/systemd/system/karvis.service`

```ini
[Unit]
Description=Karvis AI Assistant
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/karvis/src
ExecStart=/opt/karvis/src/venv/bin/python app.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> ⚠️ `ExecStart` 使用 **venv 内的 python**（`/opt/karvis/src/venv/bin/python`），不是系统 python3

### 常用 systemctl 命令

| 命令 | 说明 |
|------|------|
| `sudo systemctl start karvis` | 启动服务 |
| `sudo systemctl stop karvis` | 停止服务 |
| `sudo systemctl restart karvis` | 重启服务 |
| `sudo systemctl status karvis` | 查看状态 |
| `sudo systemctl enable karvis` | 开机自启 |
| `journalctl -u karvis -f` | 实时日志 |

### 修改配置后需要重新加载

```bash
sudo systemctl daemon-reload
sudo systemctl restart karvis
```

### 一键修复 systemd 配置（如果被覆盖）

```bash
sudo tee /etc/systemd/system/karvis.service << 'EOF'
[Unit]
Description=Karvis AI Assistant
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/karvis/src
ExecStart=/opt/karvis/src/venv/bin/python app.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl restart karvis
sudo systemctl status karvis
```

## 六、常见问题

### Q1: `cd: /root/karvis: No such file or directory`

**原因**: 项目安装在 `/opt/karvis/`，不是 `/root/karvis/`

**解决**: 使用正确路径 `cd /opt/karvis`

### Q2: `nohup: failed to run command 'python': No such file or directory`

**原因**: 服务器上没有裸 `python` 命令

**解决**: 使用 venv Python 或系统 `python3`

```bash
# venv Python（推荐）
/opt/karvis/src/venv/bin/python

# 系统 Python3
/usr/bin/python3
```

### Q3: `ModuleNotFoundError: No module named 'flask'`

**原因**: 使用了系统 Python3 而不是 venv，导致找不到已安装的依赖

**解决方案 A（推荐）**: 修改 systemd 使用 venv Python
```bash
# ExecStart 改为:
ExecStart=/opt/karvis/src/venv/bin/python app.py
```

**解决方案 B**: 用 venv 重新安装依赖
```bash
cd /opt/karvis/src && source venv/bin/activate && pip install -r requirements.txt && deactivate
```

**解决方案 C**: 用系统 Python3 安装依赖
```bash
pip3 install -r /opt/karvis/src/requirements.txt
```

### Q4: systemd 服务启动失败 `code=exited, status=1/FAILURE`

**可能原因**:
1. `ExecStart` 路径错误（比如指向了不存在的 venv）
2. `WorkingDirectory` 路径错误

**排查**:
```bash
# 查看服务状态
sudo systemctl status karvis

# 查看详细日志
journalctl -u karvis --no-pager | tail -50
```

**修复**:
```bash
# 查看当前配置
cat /etc/systemd/system/karvis.service

# 修改配置
sudo nano /etc/systemd/system/karvis.service

# 确保 ExecStart 使用正确的 python3 路径
# ExecStart=/usr/bin/python3 app.py

# 重新加载并重启
sudo systemctl daemon-reload
sudo systemctl restart karvis
```

### Q4: 更新后服务没启动

**检查**:
```bash
sudo systemctl status karvis
```

**手动启动**:
```bash
sudo systemctl start karvis
```

### Q5: 查看错误日志

```bash
journalctl -u karvis --no-pager | grep -i error | tail -20
```
