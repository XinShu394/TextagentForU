# 待办管理功能改进文档

**更新日期**: 2026-03-20  
**版本**: V14

## 一、功能概述

本次更新主要改进了待办事项的管理逻辑，新增数据管理功能，提升用户体验。

### 主要改动

| 功能 | Skill | 说明 |
|------|-------|------|
| 删除待办 | `todo.delete` | 新增：直接从列表移除，不标记完成 |
| 标记完成 | `todo.done` | 优化：仅用于用户表达完成意图 |
| 自动完成 | 系统自动 | 新增：一次性提醒过期后自动标注完成 |
| 意图确认 | `clarify` | 新增：意图不明确时向用户确认 |
| 数据导出 | `data.export` | 新增：导出用户所有数据 |
| 数据销毁 | `data.destroy` | 新增：彻底删除用户所有数据 |

## 二、删除待办 vs 标记完成

### 2.1 功能区分

之前 `todo.done` 承担了"完成"和"删除"两种语义，容易混淆。现在拆分为两个独立的 skill：

| 操作 | Skill | 触发词示例 | 效果 |
|------|-------|-----------|------|
| **删除待办** | `todo.delete` | "删除/删掉/去掉待办"、"不要这个了" | 直接从列表移除，不保留记录 |
| **标记完成** | `todo.done` | "做完了/搞定了/我已经XX了" | 移到已完成区域，保留记录 |

### 2.2 使用示例

```
用户: 把买猫粮那个待办删了
→ todo.delete {keyword: "猫粮"}
→ 直接从 Todo.md 移除该条目

用户: 猫粮买好了
→ todo.done {keyword: "猫粮"}  
→ 该条目移到 Todo.md 的「已完成」区域
```

### 2.3 批量操作

两个 skill 都支持 `indices` 参数进行批量操作：

```
用户: 删掉第 2-5 个待办
→ todo.delete {indices: "2-5"}

用户: 1、3、5 做完了
→ todo.done {indices: "1,3,5"}
```

## 三、自动完成机制

### 3.1 触发条件

一次性提醒（非循环待办）满足以下条件时，系统会自动标注为完成：

1. `remind_at` 时间已过
2. 已经向用户发送过提醒通知（`last_notified` 非空）

### 3.2 处理逻辑

```
过期 + 已通知 → 自动从「进行中」移到「已完成」
                 ↓
              Todo.md 中添加标记：✅ `2026-03-20` (自动完成)
```

### 3.3 代码位置

`src/skills/todo_manage.py` → `check_todos()` 函数

## 四、意图确认机制

### 4.1 新增 `clarify` skill

当用户意图不够明确时，Flash 层会返回 `clarify` skill，向用户确认具体操作。

### 4.2 触发场景

```
用户: 那个待办怎么处理
AI: 你是想删除这个待办，还是标记为已完成？

用户: 算了算了
AI: 你是想取消这个任务，还是有其他想法？
```

### 4.3 代码位置

`src/prompts.py` → `FLASH_QUICK_PROMPT`

## 五、数据管理功能

### 5.1 数据导出 (`data.export`)

用户说"导出我的数据"时，汇总返回所有用户数据：

- 用户配置（昵称、AI名、偏好）
- 长期记忆
- 快速笔记（近30条）
- 待办事项
- 归档笔记（读书、影视、情感、生活趣事等）
- 近期日报（7天）

**触发词**: "导出数据"、"给我所有信息"、"数据迁移"

### 5.2 数据销毁 (`data.destroy`)

用户说"删除我的所有数据"时，彻底删除用户信息。

**安全机制**:
1. 第一次请求：返回确认提示，生成 5 分钟有效的确认令牌
2. 用户确认后（`confirm=true`）：执行删除
3. 删除内容：用户目录、注册表记录、访问令牌
4. 管理员账号禁止自我销毁

**触发词**: "删除我的所有数据"、"销毁我的账号"、"清除我的信息"

### 5.3 代码位置

新文件: `src/skills/data_manage.py`

## 九、注意事项

1. **循环待办不会被自动完成**：只有一次性提醒会触发自动完成机制
2. **数据销毁不可恢复**：确认后数据将被彻底删除，无法找回
3. **管理员保护**：管理员账号无法通过 `data.destroy` 删除自己
