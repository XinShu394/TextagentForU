# 2026-03-24 DNS 与部署问题排查

**日期**: 2026-03-24  
**状态**: 🔴 问题已定位，待修复

---

## 一、问题现象

1. 企业微信发消息后，**收不到回复**
2. Flask 日志中**没有任何 `/wework` 请求记录**
3. `curl https://textagent.cn/wework` 返回 **GitHub Pages 404 页面**
4. `curl http://127.0.0.1:9000/wework` **正常**（Flask 服务正常运行）

---

## 二、根因分析

### DNS 解析冲突

`textagent.cn` 域名的 DNS A 记录指向了 **GitHub Pages IP**（用于 landing page），而不是云服务器 IP：

```
当前 DNS 解析结果：
textagent.cn → 185.199.108.153  (GitHub Pages)
textagent.cn → 185.199.109.153  (GitHub Pages)
textagent.cn → 185.199.110.153  (GitHub Pages)
textagent.cn → 185.199.111.153  (GitHub Pages)

期望：
textagent.cn → 8.163.38.4      (阿里云 ECS 服务器)
```

### 原因

之前部署 landing page 时（参考 `deploy-landing-page.md`），在 Cloudflare 上将 `textagent.cn` 的 A 记录改为了 GitHub Pages 的 IP，导致：

- ✅ Landing page (`textagent.cn`) 可以正常访问
- ❌ 企微回调 (`textagent.cn/wework`) 请求被路由到 GitHub 而不是服务器
- ❌ Web 面板 (`textagent.cn/web/*`) 也无法访问

**两个服务（Landing Page 和 API 后端）共用了同一个域名，产生冲突。**

### Scheduler 内部调用问题（次要）

`/system` 端点的 scheduler 内部 HTTP 请求报 `400 ClientDisconnected`，这是 Flask 开发服务器的已知问题，**不影响企微消息收发**。后续可通过 gunicorn 解决。

## 四、解决方案

### 方案：使用子域名分离两个服务

| 域名 | 用途 | DNS 指向 |
|------|------|----------|
| `textagent.cn` | 阿里云 ECS（API + 企微回调 + Web 面板）| `8.163.38.4` |
| `www.textagent.cn` | GitHub Pages（Landing Page）| `xinshu394.github.io` |

#### 具体操作步骤

**步骤 1：修改 Cloudflare DNS**

1. 登录 Cloudflare → `textagent.cn` 的 DNS 管理页面
2. **删除**所有指向 GitHub Pages 的 A 记录（185.199.x.153 那四条）
3. **添加**以下记录：

| Type  | Name | Content           | Proxy status |
|-------|------|-------------------|-------------|
| A     | @    | 8.163.38.4        | DNS only    |
| CNAME | www  | xinshu394.github.io | DNS only  |

**步骤 2：修改 GitHub Pages CNAME**

把 `landing/CNAME` 文件内容从 `textagent.cn` 改为 `www.textagent.cn`，并推送到 `Textagentweb` 仓库。

**步骤 3：等待 DNS 生效（1-10 分钟）**

**步骤 4：验证**

```bash
# 验证 API 服务
curl https://textagent.cn/wework?msg_signature=test&timestamp=123&nonce=abc&echostr=test
# 应该收到 Flask 的验证响应

# 验证 Landing Page
curl https://www.textagent.cn
# 应该返回 landing page 内容
```

**步骤 5：验证 SSL 证书**

- `textagent.cn` 的 SSL 证书已经在服务器上（Let's Encrypt），DNS 指回来后自动生效
- `www.textagent.cn` 的 SSL 由 GitHub Pages 自动颁发

---

## 五、注意事项

1. DNS 修改后，`textagent.cn` 上的 Let's Encrypt 证书可能需要重新续期（因为之前指向了 GitHub）
2. 企微后台的回调 URL `https://textagent.cn/wework` **不需要修改**
3. Landing page 需要通过 `www.textagent.cn` 访问（或后续考虑在 Nginx 上同时托管 landing page）
4. GitHub Pages 仓库的 CNAME 文件必须同步更新
